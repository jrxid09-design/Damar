## Phase 2 design as built
- **Multiple keys per connection** (`provider-keys.cjs`, registry): bulk import one per line (trimmed, dedupe vs. existing incl. the primary key, invalid lines counted, max 256/connection, 150 KB body); each key DPAPI-stored under `<connection>--<kid>` (connection ids may no longer contain `--`; `combos` is reserved); views carry only `…last4`, status (`ok/error/cooldown/disabled/untested`), last OK, last error, cooldown-until; enable/disable/delete per key; the legacy single key is the `primary` slot.
- **Rotation + cooldown/failover**: per connection `round-robin | fill-first (priority) | lru`. Outcomes 401/403 park the key for `maxCooldownMs`; 408/429/5xx/network back off `cooldownMs·2^(n-1)` (capped); ok resets. Failover only on those; other 4xx return to the caller. At most **6 attempts** per request across keys/targets — never infinite. Health persisted (debounced) in `provider-health.json`; routing settings (`cooldownMs` 1 s–1 h, `maxCooldownMs` ≤ 24 h) validated and stored in `provider-connections.json`.
- **Meter**: HTTP refusals (provider answered 4xx/5xx) now settle as **zero tokens** (`HTTP_<status>_REFUSED`) instead of locking the meter, so failover is possible; transport failures, missing usage and bound violations stay fail-closed (ponytail: assumes refused requests are not billed). Canonical path: the router sits **inside** the meter (one reservation per logical request, key/target chosen per attempt). Gateway/tests: every upstream attempt is reserved/settled through `budget.run()` (same ledger, caps, grant limits, `byteInputBound` with the connection's `injectedTokens`).
- **Tests** (`provider-router.cjs`): key test = `GET /models` with that key (no tokens); bulk = all keys; model test = one tiny completion (max 8 tokens), labelled *spends tokens*, metered, grant-required; a key test can add a completion with that exact key. Results update key health.
- **Catalog / aliases / combos**: per connection Owner-added model ids and aliases (`alias → model`, resolved before dispatch); combos = named virtual model, ordered `(connection, model)` targets (1–8), `fallback` or `round-robin`, ungranted/missing targets skipped. Combos appear as provider `combos` (CLI `provider use combos <name>`, model pick, Settings, Pandawa via the canonical runtime pointed at a sentinel URL that the router maps), in the gateway catalog, and through `registry.target()`.
- **`registry.target()` (cognitive agent's Pandawa hook, kept)**: now resolves aliases to the real model, `combos/<name>` to its first granted target, and takes the key from the rotation pool. One-token edit in `pandawa-team.cjs:83`: request body uses `target.model` (was the unresolved name). That path still bypasses the usage meter and failover (its own receipts) — suggestion for the cognitive agent: call `router.dispatch()`.
- **DAMAR gateway** (`gateway.cjs`): separate listener, **off by default**, `127.0.0.1:29631` (port and LAN bind `0.0.0.0` configurable in Control, with a warning). Why a separate port: the listener only knows `/v1/*` (everything else 404), the R9 admin API and Owner/requester tokens are not reachable through it, and a LAN bind exposes only the gateway. Endpoints: `GET /v1/models`, `POST /v1/chat/completions` (stream + non-stream; tools/images passed through untouched; `stream_options.include_usage` added so streams are metered), `/v1/completions`, `/v1/embeddings` passthrough. Model ids: `<connection>/<model|alias>` or a combo name; each needs an Owner grant. Keys: `dmr-` + 32 random bytes, shown once, stored as SHA-256 + prefix, label, allowed models/combos (`*` or list), optional limits (`requests`, `totalTokens`), usage (requests, input/output tokens, last used) attributed from the shared ledger rows (`source:'gateway', gatewayKey`). OpenAI-style error bodies. Config snippets for opencode (`@ai-sdk/openai-compatible` provider block — **verified live with opencode v2.2.7**), Hermes Agent (env `OPENAI_BASE_URL`/`OPENAI_API_KEY` — format **unverified**), generic curl.
- **Admin routes** (`provider-admin-routes.cjs`, Owner only, mounted by one hook line in `r9-routes.cjs`): `/api/r9/provider-admin/{state,keys,strategy,routing,test,catalog,combos}`, `/api/r9/gateway`. No response ever carries a provider key; a gateway key appears once in `create-key`.
- **Control** (`control.js`, Providers view only): per connection a "Keys & rotation" block (masked keys table with status/last OK/last error/cooldown, Test / Enable·Disable / Delete, Import keys…, Test all keys, Test model… (spends tokens), Rotation…, Catalog…); panels "Combos" (+ New combo…, Routing…) and "DAMAR Gateway" (status, bind, base URL, keys with usage, Create key… → key shown once in the drawer, Revoke, Gateway settings… with LAN warning, copy-ready opencode/Hermes/generic snippets). Reads `padmin` (`/api/r9/provider-admin/state`). CC2 helpers only (panel/kv/table/btn/statusBadge). English source strings, Indonesian via the existing `L()`/`cli.language`.
- **Docs**: GETTING_STARTED provider section gains keys/rotation, combos and the gateway.

## Remaining risks
1. Owner-store migration not executed (classifier block) — needs the command above to be run with Owner approval.
2. The usage meter serializes live calls (one lock): a long gateway stream delays CLI turns and other gateway calls. ponytail: global lock; per-connection reservations if concurrency matters.
3. Refused HTTP calls settle as zero tokens (assumption: providers don't bill refusals).
4. Gateway uses Node `fetch` (no 300 s idle workaround that the turn path has) — very long silent streams may be cut by undici's body timeout.
5. `injectedTokens` default 4096 is too small for routers that inject large hidden prompts (seen ~4.4k); Owner sets it per connection (no UI field yet besides `/connect`; Control connect dialog could expose it).
6. Pandawa team (`pandawa-team.cjs`) calls providers directly: no failover/metering through the router (cognitive agent's design).
7. Hermes snippet format unverified; opencode verified. Gateway `/v1/models` lists connection models only after a `/models` fetch in the current session (combos always).
8. `core-snapshot` re-pin diverges from canonical C:\Workspace\Damar by two text edits until canonical is updated.
9. Interactive probes (conpty/visible) updated but not run (29623 / GUI).
